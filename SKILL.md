## When to Use

- Голая ссылка на видео/аудио/медиа-контент (YouTube и любые сайты yt-dlp)
  БЕЗ какого-либо вопроса или команды — триггер по умолчанию: скачать,
  транскрибировать, пересказать. Уточняющий вопрос («что сделать со ссылкой?»)
  задавать ЗАПРЕЩЕНО.
- Запрос вида «о чём видео», «о чём ролик», «что в этом видео», «кратко содержание
  видео» — в любом близком по смыслу wording'е — со ссылкой на видео.
- Ссылка + дополнительные вопросы к видео в одном запросе («о чём видео и как там
  настроить X?») — отвечать и на них по транскрипту.
- DON'T use for: «скачай видео» без пересказа (чистый yt-dlp), «распознай аудио,
  где ссылку уже дали раньше» (чистый mlx-whisper), живые стримы.

# Video Summary («о чём видео»)

Триггер: (а) пользователь присылает ссылку на видео/аудио/медиа-контент (YouTube и
любые сайты yt-dlp) БЕЗ какой-либо команды — одна голая ссылка или ссылка с
парой слов вокруг; (б) пользователь пишет «о чём видео / о чём ролик / кратко
содержание» или подобный по смыслу вопрос и прикладывает ссылку. В обоих случаях
действие одно: скачать → транскрибировать → пересказать, без уточняющих вопросов.
Плюс: если в том же запросе есть дополнительные вопросы к видео — ответить и на них.

Это оркестратор над двумя скиллами — строго в этом порядке:

1. `media/yt-dlp` — скачать аудио
2. `media/mlx-whisper` — распознать речь в текст

## Procedure

1. **Загрузить оба скилла** (`skill_view media/yt-dlp`, `skill_view media/mlx-whisper`) и следовать их процедурам. Ниже — только склейка и гейты.

2. **Метаданные ДО скачивания** (это и шаг детекта языка):
   ```bash
   ~/.local/bin/yt-dlp --js-runtimes node --skip-download \
     --print "%(title)s | %(uploader)s | %(duration)s сек | %(view_count)s | %(description).500B" <URL>
   ```
   По заголовку/описанию определить язык речи (гейт шага 4 скилла mlx-whisper:
   источник языка должен быть называемым — «заголовок EN», либо детект на 30 с).
   Привычка/дефолт «ru» запрещены — видео бывает на любом языке.

3. **Скачать аудио** (обычный путь, mp3 в result-yt-dlp):
   ```bash
   python3 ~/.hermes/skills/media/yt-dlp/scripts/download_dated.py --audio <URL>
   ```

3b. **Субтитры — всегда пытаться скачать** (если у контента они есть в любом виде —
   ручные или auto): идут в LLM-коррекцию «вторым мнением» и заметно чинят ослышки
   (имена, термины). Язык — тот, что определён на шаге 2:
   ```bash
   ~/.local/bin/yt-dlp --js-runtimes node --skip-download --write-subs --write-auto-subs \
     --sub-langs "<lang>.*,<lang>" --sub-format "srt/vtt/best" \
     -o "/tmp/subs/%(title).100B.%(ext)s" --no-playlist <URL>
   ```
   Скачалось несколько вариантов (напр. `en-orig` и `en`) — брать ручные/оригинальные
   (`-orig`), а не auto. Ничего не скачалось — идём дальше без `--subs`, это не блокер.

4. **Транскрибировать** (длинные файлы — только `terminal(background=true)` +
   `process wait`; скилл mlx-whisper: VAD+STT+LLM-коррекция, ~7 мин на 40-мин аудио):
   ```bash
   ~/.local/share/uv/tools/mlx-whisper/bin/python \
     ~/.hermes/skills/media/mlx-whisper/scripts/vad_transcribe.py "<mp3>" \
     --language <detected> \
     --terms "<имена/термины из заголовка и описания через запятую>" \
     --subs "/tmp/subs/<файл субтитров>.srt"   # если шаг 3b дал файл
   ```
   `--subs` передаёт субтитры в LLM-этап как «второе мнение» поверх транскрипта Whisper
   (модель рассуждает своими знаниями, числа всегда остаются от Whisper — числовой гейт
   в коде; подробности архитектуры — в скилле mlx-whisper). Использование субтитров
   фиксируется в шапке MD.
   `--terms` — имена/термины из заголовка и описания через запятую: LLM-этап
   исправляет их написание в транскрипте (баг UnboundLocalError при пустом
   LLM-этапе уже исправлен, коммит 527c906 — без `--terms` скрипт тоже работает).

5. **Прочитать MD-результат целиком** (`read_file`) из `~/result-mlx-whisper/`.

6. **Ответ пользователю** (на языке запроса юзера):
   - **Первая строка ответа — исходная ссылка**, которую прислал юзер (дословно, как в
     его сообщении, включая si-параметры и т.п.), чтобы пересказ однозначно
     привязывался к конкретному контенту.
   - Далее — одной строкой: название видео, автор/канал, длительность, язык.

   **Цель резюме**: передать основные идеи, существенные факты, аргументы и выводы
   автора без искажения смысла.

   **Структура (строго, заголовки как указано):**
   ```
   # Главная мысль
   1–2 предложения.

   # Ключевые тезисы
   Маркированные пункты. Один пункт — одна законченная мысль.
   Между пунктами — пустая строка (для удобства чтения).
   Количество пунктов определяется содержимым материала: столько, сколько
   нужно, чтобы покрыть все существенные идеи и выводы без второстепенных
   деталей; жёсткого ограничения нет. Общий объём резюме — ≤4000 символов.

   # Вывод
   1–3 предложения: основной итог или практическое значение текста.
   ```
   Объём резюме — не более 4000 символов.

   **Язык:**
   - Грамотный литературный русский, нейтральный информационно-деловой стиль.
   - Без разговорной лексики, сленга, жаргона, эмоциональных оценок, риторических
     вопросов и фамильярных обращений.
   - Без канцелярита и чрезмерно сложных оборотов.
   - Предложения логичные, законченные, грамматически корректные; предпочтительны
     короткие и средние; длинные сложные разбивать, если это улучшает читаемость.

   **Содержание:**
   - Сохранять ключевые факты, даты, цифры, имена, причинно-следственные связи и
     оговорки автора.
   - Не добавлять собственных интерпретаций, предположений и сведений, которых нет
     в источнике.
   - Исключать повторы, второстепенные детали и иллюстративные примеры, если они не
     важны для понимания вывода.
   - Противоречия и неопределённости в тексте — кратко отражать, а не устранять
     от себя.
   - Таймкоды в резюме запрещены — они нужны только внутри для навигации по
     транскрипту.

   **Внутренняя проверка перед отправкой:** (1) нет фактических искажений; (2) все
   предложения грамматически корректны; (3) нет разговорной лексики, повторов и
   «воды»; (4) структура соблюдена; (5) резюме понятно без обращения к исходнику.

   - **Ответы на дополнительные вопросы из запроса** — отдельным блоком ПОСЛЕ
     резюме (структуру резюме они не нарушают), цитируя конкретные места
     транскрипта (по таймстампу — тут таймкоды уместны), а не пересказ.
   - Если что-то в транскрипте распознано ненадёжно (имена, термины, «каша») —
     сказать прямо после резюме отдельной пометкой и указать, на какие фрагменты
     это влияет.

## Pitfalls

- **Язык — гейт**: инцидент 2026-09-02 — 39-мин английское видео прогнали с
  `--language ru` «по привычке» → полкаша и полный перезапуск. Источник языка
  называть явно; сомнение → детект на первых 30 с.
- Метаданные считать до скачивания: они же дают title для `--terms`.
- **Формат резюме (2026-09-11)**: строгая структура «# Главная мысль / # Ключевые
  тезисы / # Вывод» (см. шаг 6), нейтральный информационно-деловой стиль, без
  разговорной лексики и «воды», ≤4000 символов. Разговорный «пересказ другу»
  отменён. Таймкоды в резюме запрещены — остаются только в ответах на доп.
  вопросы (цитаты из транскрипта).
- Оба артефакта (mp3 + MD) остаются в `~/result-yt-dlp/` и `~/result-mlx-whisper/` —
  когда юзер потом задаёт доп. вопросы по видео, отвечать по сохранённому
  транскрипту без повторной транскрипции.
- **Доп. вопросы после пересказа — только по готовому транскрипту** (урок
  2026-09-04): полный MD уже содержит всё содержание видео, поэтому для ответов
  на последующие вопросы НЕ ходить в интернет (tavily/web_search) и НЕ вызывать
  снова yt-dlp (метаданные, описание, субтитры) — сначала перечитать
  `~/result-mlx-whisper/YYYY-MM-DD_<имя>.md` (путь виден в заголовке MD, источник
  mp3 — в метаданных) и цитировать ответ с таймстампами оттуда. Внешние
  инструменты — только если в транскрипте реально нет нужных данных (например,
  юзер спрашивает про то, чего в речи не было: описание под роликом, ссылки,
  комментарии).
